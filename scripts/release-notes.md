## 本次更新（0.4.1）

### 导入曲库快了一倍半 —— 顺手挖出一个自伤的写盘 bug

0.4.1 只做一件事：把「添加音乐文件夹 / 重扫曲库」这条路修快。

**根因**：生成 400px 封面缩略图时，代码把**裸文件句柄**交给了 JPEG 编码器，而这个编码器是
**逐字节**写出熵编码数据的 —— 落到文件上就是「每字节一次系统调用」。一张 36 KB 的缩略图
约 3.6 万次 `WriteFile`，实测 **52.7 ms/张**；同一张图编码到内存只要 **3.2 ms**。
整次导入最大的一笔开销就来自这里。

改法是一行 `BufWriter`。输出与修复前**逐字节相同**（已对 268 张缩略图逐一 SHA-256 核对）。

**实测（本机，272 首 / 8.52 GB，Ryzen 7 9700X 8 核）**：

| 指标 | 0.4.0 | 0.4.1 |
| --- | --- | --- |
| 首次导入（全新安装） | 2.60 s | **1.47 s** |
| 导入吞吐 | ~104 文件/秒 | **~185 文件/秒** |
| 逐文件解析中位耗时 | 64 ~ 82 ms | **25 ms** |
| 每次增量重扫 | 约 29 ms | 约 29 ms（本就不解析封面，未变） |

导入时间约 **97% 花在解析内嵌封面**；目录遍历、stat 比对、入库、差集删除、封面 GC 加起来
不到 40 ms。10 000 首的曲库，增量重扫约 **0.4 秒**。

另外，扫描现在会在日志里打印**分阶段耗时**（收集 / 开库 / 读戳 / 比对 / 解析 / 入库 /
差集删除 / GC / 收尾），以后定位「扫库慢」不用再猜。

### 支持的格式一览

| 扩展名 | 编码 / 容器 | 解码器 |
| --- | --- | --- |
| .mp3 | MPEG 音频（MP3） | symphonia |
| .flac | FLAC | symphonia |
| .wav | PCM / ADPCM（RIFF） | symphonia |
| .aiff | PCM（AIFF） | symphonia |
| .caf | PCM（CAF） | symphonia |
| .ogg / .oga | Ogg 容器内的 Vorbis | symphonia |
| .m4a / .m4b | MP4 容器内的 AAC 或 ALAC | symphonia |
| .opus | Ogg Opus | opus-pure（自行接入） |
| .aac | 裸 AAC / ADTS 流 | 自写 ADTS 解封装 + symphonia 的 AAC 解码器 |
| .dsf / .dff | DSD | 自研：1-bit 查表低通 + 整数抽取转 PCM |

（音频内核与 0.4.0 一致：多相 sinc 重采样、WASAPI 独占 + 自动回退、DSD 1-bit 查表解码。）

**暂不支持**：APE、WavPack、TAK、Musepack(MPC)、WMA(ASF)、Speex、RealAudio，以及 CUE 整轨分轨。

### 输出说明

- **共享模式**：按设备当前采样率做一次多相 sinc 转换（0.4.0 起不再是线性插值）。
- **独占模式**：优先按曲目采样率协商，争取 bit-perfect；设备不支持时自动回退共享并在设置页说明原因。
- DSD 的原生直出（DoP）需要 DAC 支持 176.4kHz 独占，属于后续版本。
