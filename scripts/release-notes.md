## 本次更新（0.2.9）

### WASAPI 独占输出（bit-perfect 取向）

设置 →「独占输出」新增**输出模式**：自动（优先独占）/ 独占 / 共享。独占模式绕过系统混音器，
按设备的原生格式输出。**能力边界完全现场探测**，不假设你的设备支持什么：

- **逐曲按采样率协商**：曲目采样率 → 设备默认率 → 48000 → 44100；
  每个采样率下再按 24/32 → 24/24 → 32/32 → 32f → 16/16 依次试位深。
- 命中驱动的「缓冲未对齐」（44.1kHz 上很常见）会**自动对齐后重试**。
- **失败一律回退共享并说明原因**（设备被别的程序占用 / 系统禁用了独占控制 / 设备不支持该格式…），
  绝不会有「一点声音都没有」的静默失败。
- 设置页实时显示**当前生效的后端与实际格式**（例：`独占模式：44100/24/32`）；
  在系统里改完独占设置后，点「重新尝试独占」即可重新协商，不用重启应用。

本机实测（Realtek HD Audio 2nd output）：44.1kHz 走通对齐重试，独占 44100/24/32 正常出声，
暂停 / 快进 / 切歌 / 音量与共享模式一致。

### 本次修复

- **DSD（.dsf）快进时出现「电音」，跳得越远越长** ——
  根因：rodio 的原地 seek 实际是在**音频线程**上执行的，而 DSD 的定位是「重开容器 + 逐块跳过到目标」，
  工作量与跳转距离成正比；跳到 85% 处会让渲染线程停 1.25 秒，独占缓冲排空 ⇒ 电音。
  修法：① 这类定位一律改到引擎线程执行（只有 symphonia 的毫秒级定位才允许原地 seek）；
  ② DSF 是分块结构化的容器，定位改为直接文件定位（**O(1)**）。
  实测（195MB / 276s 的 .dsf 跳到 85%）：定位延迟 `1192ms → 0.0ms`，
  音频线程最长停顿 `1250ms → 5.7ms`（无欠载、无电音）。
- **裸 AAC（.aac）** 的定位原来每帧 seek 一次（每帧一次系统调用），已改为顺序读帧头，远跳明显更快。
- 独占回退共享后，即使在系统里重新允许独占，设置页也会一直显示旧的回退警告；
  现在点「重新尝试独占」即可重新协商并刷新。

### 支持的格式一览

| 扩展名 | 编码 / 容器 | 解码器 |
| --- | --- | --- |
| .mp3 | MPEG 音频（MP3） | symphonia |
| .flac | FLAC | symphonia |
| .wav | PCM / ADPCM（RIFF） | symphonia |
| .aiff | PCM（AIFF） | symphonia |
| .caf | PCM（CAF） | symphonia |
| .ogg / .oga | Ogg 容器内的 Vorbis | symphonia |
| .m4a / .m4b | MP4 容器内的 AAC 或 ALAC | symphonia |
| .opus | Ogg Opus | opus-pure（自行接入） |
| .aac | 裸 AAC / ADTS 流 | 自写 ADTS 解封装 + symphonia 的 AAC 解码器 |
| .dsf / .dff | DSD | 自研：低通 + 整数抽取转 PCM |

**暂不支持**：APE、WavPack、TAK、Musepack(MPC)、WMA(ASF)、Speex、RealAudio，以及 CUE 整轨分轨。

### 输出说明

- **共享模式**：所有音源按输出设备的格式做采样率 / 声道转换。
- **独占模式**：优先按曲目采样率协商，争取 bit-perfect；设备不支持时自动回退共享并在设置页说明原因。
- DSD 的原生直出（DoP）需要 DAC 支持 176.4kHz 独占，属于后续版本。
